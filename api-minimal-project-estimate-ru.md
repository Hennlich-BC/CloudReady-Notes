# Оценка минимального проекта REST API

Документ дополняет `api-infrastructure-ru.md`. Оценка предварительная, рассчитана для одного специалиста при 8-часовом рабочем дне и не является коммерческим предложением.

## Состав минимального проекта

В MVP входят:

- внутренний Linux-сервер, Docker Engine и Docker Compose;
- FastAPI с версионированным REST/OpenAPI-контрактом;
- PostgreSQL для операций, статусов и идемпотентности;
- RabbitMQ и один Celery worker;
- Typst worker для одного согласованного PDF-документа;
- хранение в Docker volumes без обязательного MinIO;
- HTTPS, API credentials или OAuth 2.0 в зависимости от готовности инфраструктуры;
- один AL client codeunit и setup page в Business Central;
- статусы асинхронных операций и получение сформированного PDF;
- базовые логи, healthchecks, backup и инструкция по эксплуатации;
- unit, integration и приёмочные тесты одного сквозного сценария.

В MVP не входят все перевозчики, EDI, FTP/SFTP, FinStat, OCR, универсальный редактор шаблонов, отказоустойчивый кластер, полный мониторинг Grafana и миграция всех существующих PDF-отчётов.

## Оценка трудозатрат

| Этап | Рабочие дни | Результат |
|---|---:|---|
| Уточнение требований и архитектура | 3–4 | Контракт, схема компонентов, security и acceptance criteria |
| Linux/Docker-инфраструктура | 4–6 | Compose, networks, volumes, secrets, TLS, healthchecks |
| Основа API и очередь операций | 6–8 | FastAPI, PostgreSQL, RabbitMQ, Celery, идемпотентность и статусы |
| Typst/PDF-сценарий | 5–7 | Один production-like шаблон, JSON mapping, генерация и выдача PDF |
| Интеграция с Business Central | 5–7 | AL client, setup, permissions, отправка задания и получение результата |
| Логи, backup и документация | 3–4 | Correlation ID, журнал ошибок, backup/restore и runbook |
| Тестирование и исправления | 8–11 | Unit, integration, негативные, security и небольшой нагрузочный тест |
| Внедрение и приёмка | 6–8 | Установка, настройка сети/сертификатов, UAT, исправления и передача |
| **Итого** | **40–55 дней** | **320–440 часов** |

Рекомендуемый резерв — 15%, то есть плановый бюджет проекта составляет **46–63 рабочих дня или 368–506 часов**.

## Календарный срок для одного человека

| Фаза | Ожидаемый срок |
|---|---:|
| Реализация | 5–7 недель |
| Тестирование и стабилизация | 2–3 недели |
| Внедрение и UAT | 1–2 недели |
| **Чистый срок** | **8–12 недель** |
| **Реалистичный календарный срок с согласованиями** | **10–14 недель** |

Чистый срок предполагает почти полную занятость специалиста. Ожидание Linux VM, firewall, DNS, сертификатов, учётных данных BC или решения пользователей по шаблону увеличивает календарный срок, но не обязательно трудозатраты.

## Оценка стоимости работ

Стоимость приведена в евро без НДС, оборудования, лицензий, сопровождения после запуска и расходов на внешние сервисы.

| Ставка | Базовые 320–440 часов | С резервом 368–506 часов |
|---:|---:|---:|
| 50 EUR/час | 16 000–22 000 EUR | 18 400–25 300 EUR |
| 65 EUR/час | 20 800–28 600 EUR | 23 920–32 890 EUR |
| 80 EUR/час | 25 600–35 200 EUR | 29 440–40 480 EUR |

Для предварительного бюджета разумно заложить **около 25 000–33 000 EUR без НДС** при расчётной ставке около 65 EUR/час и резерве 15%. Точная сумма определяется согласованной ставкой, способом аутентификации, готовностью Linux-сервера и сложностью первого Typst-шаблона.

## Оценка внедрения

Из общих трудозатрат на собственно внедрение приходится примерно 6–8 дней:

- подготовка Linux VM, дисков, DNS и firewall — 1–2 дня;
- установка Compose и первичная конфигурация — 1 день;
- TLS, secrets и соединение с BC — 1–2 дня;
- установка AL-компонентов и настройка — 1 день;
- backup/restore check, smoke test и UAT — 2 дня.

Если VM, DNS, сертификаты и сетевые правила готовит отдельная инфраструктурная команда, её время не включено в стоимость одного разработчика и должно оцениваться отдельно.

## План тестирования

- Unit tests: валидация моделей, mapping JSON → Typst, статусы и retry.
- Integration tests: PostgreSQL, RabbitMQ, Typst compilation и файловое хранилище.
- BC end-to-end: создание задания, polling, скачивание PDF и обработка ошибки.
- Negative tests: неверный JSON, отсутствующий template, timeout, повреждённый asset и недоступный worker.
- Security: authentication, права, ограничения размера, защита путей и отсутствие секретов в логах.
- Performance smoke test: несколько параллельных PDF и контроль CPU/RAM/очереди.
- Recovery: restart worker/API, повтор задания без дубля и восстановление из backup.

## Основные риски оценки

- Не готов внутренний Linux-сервер, DNS, TLS или firewall.
- Не определён способ аутентификации Business Central → API.
- Первый PDF имеет сложную вёрстку, нестандартные fonts или должен точно повторить существующий layout.
- Потребуется объединение/подпись PDF, а не только генерация Typst.
- Один разработчик одновременно выполняет AL, Python, DevOps и тестирование; специализированные проверки безопасности потребуют дополнительного исполнителя.
- В ходе MVP в scope добавляются перевозчики, EDI, FTP или несколько шаблонов.

Каждая новая предметная интеграция после готового MVP обычно оценивается отдельно. Простой REST-адаптер может занять 3–6 дней, сложный перевозчик/EDI — 8–20 дней, дополнительный Typst-шаблон — 2–7 дней в зависимости от макета и правил.
